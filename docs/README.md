## 写作规范

### 放置位置

| 类型 | 位置 |
|------|------|
| 用户手册 | 仓库根目录 `README.md` |
| Agent / 开发指南 | 仓库根目录 `AGENTS.md` |
| 许可证 | 仓库根目录 `LICENSE` |
| 路线图、设计、本规范 | `docs/` |
| 单功能设计 | `docs/design/<topic>.md` |

不要在根目录再堆新的 `.md`。新设计稿一律放进 `docs/design/`。

### 一份事实只写一处

- 用户能看见的功能与快捷键 → `README.md`
- 模块怎么拆、代码怎么写、有哪些坑 → `AGENTS.md`
- 还没做、准备做 → `docs/ROADMAP.md`
- 某一个功能怎么交互、怎么验收 → `docs/design/*.md`

其它文档用链接指向上述位置，不要复制整表。实现完成后：更新路线图状态，并同步 `README.md` / `AGENTS.md` 中受影响的段落。

### 文首元信息

`docs/` 下每份文档开头使用同一格式：

```markdown
> **读者**：……
> **状态**：现行 | 已完成 | 草案
> **更新**：YYYY-MM-DD
```

设计文档额外加一行实现进度，例如：`> **实现**：Phase 1–4 已完成，Phase 5 未完成`。

### 状态用词

只用这四个词，不要混用「差不多」「基本好了」：

| 用词 | 含义 |
|------|------|
| 已完成 | 代码已合入，可按验收标准使用 |
| 部分完成 | 主路径可用，文档中必须写清缺口 |
| 未开始 | 尚无实现 |
| 已取消 | 明确不做 |

### 语言与格式

- 正文中文；类型名、路径、快捷键、命令保持原文。
- 标题用中文；代码标识用反引号。
- 日期用 `YYYY-MM-DD`。
- 不要把「准备怎么改」写成「现在已经是这样」；历史决策可保留，但必须标成已完成或已过时。
